# Vendored Manager Agent Gym

This directory contains a copy of the scenario, schema, evaluator and prompt modules of
[Manager Agent Gym](https://github.com/DeepFlow-research/manager_agent_gym) (MAG) at revision
`3f7a5d4af1d31abaedbedd525a0090452926fef4`, released under the MIT license (see `NOTICE`).
Ergon's native Manager Gym adapter (the modules one directory up) builds on these files through
`manager_gym/upstream.py`, and never imports from this tree directly.

## What is vendored, and how

Files keep their upstream paths: `examples/…` holds the 20 scenarios and their catalogue,
`manager_agent_gym/…` holds the schemas, evaluators and prompts they depend on. The tree is
generated by `scripts/vendor_mag.py`, and every file falls into one of four kinds, recorded in
`MANIFEST.json` with its hash:

| Kind | Meaning |
|---|---|
| `verbatim` | Byte-identical to upstream. |
| `imports_rewritten` | Identical to upstream except for import statements (see below). |
| `shim` | Hand-written stand-in for an upstream runtime module. |
| `package_init` | Empty `__init__.py`; upstream package initialisers import MAG's runtime. |

Import statements are rewritten by three mechanical rules and nothing else is edited:

1. Absolute imports of `manager_agent_gym` and `examples` gain the vendor package prefix.
2. Imports from a package whose `__init__.py` is not vendored point at the defining submodule.
3. `stakeholder_evaluator.py` checks for `StakeholderConfig`, because Ergon keeps agent
   configurations, not live agents, in `Workflow.agents`.

Shims replace the parts of MAG that Ergon implements natively:

| Upstream module | Shim |
|---|---|
| `core/common/logging.py` | A standard library `logger`. |
| `core/communication/service.py` | An empty `CommunicationService` type; the evaluators never use it. |
| `core/workflow_agents/interface.py` | `AgentInterface = AgentConfig`. |
| `core/workflow_agents/stakeholder_agent.py` | `StakeholderAgent(config)` returns `config`. |
| `schemas/execution/manager_actions.py` | `ActionResult = Any`; Ergon records native action results. |

`MANIFEST.json` also lists, under `references`, the upstream modules that Ergon ports rather than
vendors (the execution engine, agents, manager actions and the LLM judge), with their hashes.

## Updating

Do not edit files here by hand; `test_vendor.py` fails if a file no longer matches the manifest.
To move to a new upstream revision, update `REVISION` in `scripts/vendor_mag.py`, then:

```bash
git clone https://github.com/DeepFlow-research/manager_agent_gym /tmp/mag
git -C /tmp/mag checkout <revision>
uv run python scripts/vendor_mag.py /tmp/mag
```

Changes to rubric definitions show up in `test_catalog.py`, which compares every rubric's name,
maximum score and definition hash with an inventory taken from the pinned revision.

## Known upstream issues

These are kept as-is so that rubric version 1 reproduces upstream scores. Rubric version 2, the
default, corrects them in `manager_gym/rubric_versions.py`.

| Rubric | Issue | Affects |
|---|---|---|
| ICAAP `quality` / `seeking_sourcing` | Declares no `required_context`, so it never sees tool usage and always scores 0. | Utility |
| Stakeholder `response_latency_adherence` | The function caps at 8, but `max_score` is 20. | Diagnostics |
| Operational `agent_utilization_efficiency` | Description is copied from `deadtime_efficiency`. | Diagnostics |
